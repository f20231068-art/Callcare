THE SHORT ANSWERWhat "web server" actually means here

I used "web server" for one thing that was too broad. It is a single Python program, started with carecall serve, that listens on port 8000. By itself it is only a doorway: it receives requests and calls other code. The work is done by separate modules inside the same program, and by services outside it. This page splits it up.

What the program does

Receives browser requests (sign-up, dashboard) and Twilio's webhooks. Runs the conversation agent for each call. Calls Gnani, the LLM and Twilio over the internet. Reads and writes the database. Sends traces to Langfuse.

What it does not do

It does not run Gnani's speech models. Speech-to-text and text-to-speech run on Gnani's servers; our code only holds a connection and an API key. It does not run the LLM either. It does not host the database, and it does not decide when to dial (a second program does).

The two programs plus tunnel

serve handles requests and live calls. scheduler wakes every 10 s, plans calls and dials the due ones. ngrok gives the laptop a public address. All three use the same code base and the same PostgreSQL database.

HONEST NOTESGaps found while collecting these examples

The caregiver is never actually messaged. Every alert and summary is written to notifications with sent_at set, but the "send" step only prints a line to the server console. Real SMS is off (SMS_NOTIFICATIONS), and an account created by sign-up has no caregiver phone number (the caregivers.phone column is empty). The dashboard does not show notifications either, so the only place a caregiver sees an alert is the "What the agent recorded" panel.
Call 21 went wrong, and the opening is now fixed. It was the call-back for the tablet reminder. Its transcript shows a stale line spoken as the second opening sentence ("Thank you. I will call you again at eleven thirty-six this morning", at 11:36), then a question about food instead of the tablet, and a summary of "Dinner: had pancake". The stale line came from asking the model to continue from the previous transcript; call-backs now use the scripted opening. The food question was not explained, so this page's example rows for call 21 are kept as they were recorded.
Other limits that matter here: conversation memory lives in the serve process and is lost on restart; tables are created at start-up with no migrations; there is no backup of the Docker volume.
